## Git и Работа с Кодом

**Git** - система контроля версий. Помогает отслеживать изменения в коде и работать в команде.

**Репозиторий (repo)** - папка с проектом, которая отслеживается Git. Думайте о ней как о "хранилище кода".
```
Пример: ваш проект my-app - это репозиторий
```

**Коммит (commit)** - сохранение изменений в Git с описанием что вы сделали.
```
Аналогия: как сохранение игры с пометкой "прошёл 3 уровень"
Команда: git commit -m "Добавил кнопку входа"
```

**Пушить (push)** - отправить свои коммиты на удалённый сервер (GitHub, GitLab).
```
Простыми словами: загрузить код на GitHub
Команда: git push
Аналогия: как загрузить фото в облако
```

**Пулить (pull)** - скачать изменения с удалённого сервера к себе.
```
Простыми словами: скачать последнюю версию кода
Команда: git pull
```

**Клонировать (clone)** - скачать весь репозиторий себе на компьютер.
```
Команда: git clone https://github.com/user/project.git
```

**Ветка (branch)** - параллельная версия проекта для разработки новой фичи.
```
Пример: основной код в ветке main, новую фичу делаете в ветке feature-login
```

**Мёрджить (merge)** - объединить изменения из одной ветки в другую.
```
Пример: закончили фичу → мёрджите её в main
```

**Pull Request (PR)** - запрос на добавление ваших изменений в основной код.
```
Простыми словами: "Я сделал фичу, проверьте и добавьте в проект"
```

## Разработка и Запуск

**Деплоить (deploy)** - выложить приложение в интернет, чтобы пользователи могли им пользоваться.
```
Простыми словами: опубликовать сайт/приложение онлайн
До деплоя: работает только на вашем компьютере
После деплоя: доступно по ссылке всем в интернете
```

**Production (продакшн)** - рабочая версия приложения, которую используют реальные пользователи.
```
Пример: instagram.com - это production
```

**Development (разработка)** - версия для разработки на вашем компьютере.
```
Пример: localhost:3000 - это development
```

**Localhost** - ваш компьютер. Когда запускаете проект локально.
```
Пример: http://localhost:3000
Простыми словами: сайт работает только на вашем компьютере
```

**Build (билд)** - процесс преобразования кода в готовое приложение.
```
Команда: npm run build
Пример: из React компонентов создаются HTML/CSS/JS файлы
```

**Environment (окружение)** - настройки где запускается приложение.
```
Development окружение: на вашем компьютере
Production окружение: на сервере в интернете
```

## Архитектура Приложений

**Фронтенд (Frontend)** - то, что видит пользователь. Интерфейс, кнопки, дизайн.
```
Технологии: React, Vue, HTML, CSS, JavaScript
Простыми словами: красивая часть сайта
```

**Бэкенд (Backend)** - серверная часть. Логика, база данных, обработка запросов.
```
Технологии: Node.js, Python, Go
Простыми словами: то, что работает "за кулисами"
```

**Full-stack** - и фронтенд, и бэкенд вместе.
```
Full-stack разработчик: умеет делать и красивый интерфейс, и логику на сервере
```

**API (Application Programming Interface)** - способ общения между программами.
```
Пример: ваш сайт запрашивает данные у сервера через API
GET /api/users → получить список пользователей
```

**REST API** - популярный стиль создания API.
```
GET /posts - получить посты
POST /posts - создать пост
PUT /posts/1 - обновить пост
DELETE /posts/1 - удалить пост
```

**Database (БД, База данных)** - место хранения данных приложения.
```
Примеры: PostgreSQL, MySQL, MongoDB
Простыми словами: как Excel таблица, но для приложений
```

## Инструменты и Технологии

**npm (Node Package Manager)** - менеджер пакетов для JavaScript. Устанавливает библиотеки.
```
Команда: npm install express
Простыми словами: магазин готовых решений для кода
```

**Package (пакет)** - готовая библиотека кода, которую можно установить.
```
Пример: express - пакет для создания веб-серверов
```

**Dependencies (зависимости)** - пакеты, которые нужны вашему проекту.
```
В package.json указаны все зависимости
npm install - установит все сразу
```

**CLI (Command Line Interface)** - программа управляется через текстовые команды.
```
Пример: git, npm - это CLI инструменты
Противоположность: GUI (графический интерфейс с кнопками)
```

**Framework (фреймворк)** - готовая структура для разработки приложений.
```
Примеры: Next.js, Express.js, Django
Простыми словами: готовый "скелет" приложения
```

**Library (библиотека)** - набор готовых функций для решения задач.
```
Примеры: React, lodash
Отличие от фреймворка: библиотека - инструмент, фреймворк - готовая структура
```

## DevOps и Инфраструктура

**Server (сервер)** - компьютер в интернете, где работает ваше приложение.
```
VPS, Cloud Server, Dedicated Server - разные типы серверов
```

**VPS (Virtual Private Server)** - виртуальный сервер в облаке.
```
Примеры: DigitalOcean Droplet, AWS EC2
Простыми словами: арендованный компьютер в интернете
```

**Docker** - технология для упаковки приложения со всеми зависимостями.
```
Простыми словами: контейнер с вашим приложением, который работает везде одинаково
```

**Container (контейнер)** - изолированная среда для запуска приложения.
```
Аналогия: как посылка с приложением, которая откроется на любом сервере
```

**CI/CD (Continuous Integration/Deployment)** - автоматическая проверка и деплой кода.
```
Пример: запушили код → автоматически тесты → автоматический деплой
```

**SSH (Secure Shell)** - защищённое подключение к серверу.
```
Команда: ssh user@server.com
Простыми словами: удалённое управление сервером
```

**Domain (домен)** - адрес сайта в интернете.
```
Примеры: google.com, github.com
Вместо IP адреса (192.168.1.1) используется понятное имя
```

**DNS** - система преобразования доменов в IP адреса.
```
Простыми словами: телефонная книга интернета
mysite.com → 104.26.13.45
```

## Безопасность и Конфиденциальность

**Environment Variables (.env)** - секретные настройки приложения.
```
Пример: пароли от БД, API ключи
НЕЛЬЗЯ пушить в Git!
```

**API Key** - секретный ключ для доступа к сервису.
```
Пример: ключ для работы с OpenAI API
Храните в .env файле!
```

**Token (токен)** - секретная строка для аутентификации.
```
Пример: JWT токен для входа пользователя
```

**Authentication (аутентификация)** - проверка, кто вы.
```
Простыми словами: вход в систему (логин + пароль)
```

**Authorization (авторизация)** - проверка, что вам можно делать.
```
Простыми словами: проверка прав доступа
Пример: админ может удалять пользователей, обычный юзер - нет
```

## Разное

**Localhost:3000** - адрес вашего приложения на локальном компьютере.
```
localhost = ваш компьютер
3000 = порт (номер "двери" для доступа)
```

**URL** - адрес ресурса в интернете.
```
Пример: https://github.com/user/repo
https:// - протокол
github.com - домен
/user/repo - путь
```

**Endpoint** - конкретный адрес API для выполнения действия.
```
Примеры:
/api/users - endpoint для получения пользователей
/api/login - endpoint для входа
```

**JSON** - формат обмена данными между приложениями.
```json
{
  "name": "Иван",
  "age": 25
}
```

**IDE (Integrated Development Environment)** - программа для написания кода.
```
Примеры: VS Code, WebStorm, IntelliJ IDEA
Простыми словами: Word, но для кода
```
